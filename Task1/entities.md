# Каталог сущностей

FU/RB означают отдельные системы двух банков. Все ID источников уникальны только вместе с source_system и source_bank. Common ID — новый устойчивый идентификатор; исходные ключи не перезаписываются. Для каждой сущности сохраняются source_updated_at, ingested_at, record_version и lineage к источнику.

| ID / сущность | Смысл и основные атрибуты | Связи | Источники / первое появление | Зачем в модели | Проблемы качества |
|---|---|---|---|---|---|
| E01 Customer | Физическое/юридическое лицо: customer_id, party_type, имя/наименование, birth_date либо registration_date, проверенные идентификаторы, контакты | Identifier, AgreementParty, Case, Consent, Segment | FU/RB CRM, KYC при onboarding; копии Core/Loans | Общий профиль обеих организаций | Омонимы, смена документов, дубли, общий телефон семьи, разные типы лиц |
| E02 Identifier | Соответствие: source_system, source_customer_id, customer_id, valid_from/to, match_method, confidence, review_id | Customer | Источники дают local ID; Hub создаёт crosswalk | Связать старые ключи, обратимо разделять ошибочный merge | Коллизия ID, повторное использование, один local ID назначен двум лицам |
| E03 Agreement | Продуктовый договор: agreement_id, source_id, product_id, tariff_id, status, signed_at, closed_at, master_system | AgreementParty, Account, Card, Loan, Product, Tariff | FU/RB Core (счёт), Cards (карточный договор), Loans (кредитный) | Юридические условия и статус продукта | Разные значения active, потеря версии условий, неверный владелец |
| E04 AgreementParty | Роль стороны: agreement_id, customer_id, role, valid_from/to, authority_basis | Customer, Agreement | Core/Cards/Loans после проверки прав | M:N для созаёмщика, представителя, держателя | Отсутствие владельца, представитель ошибочно принят за владельца |
| E05 Account | Учётный счёт: account_id, agreement_id, branch_id, number_token, currency, type, status, opened_at | Agreement, Branch, Card, Posting, Loan | FU/RB Core при открытии | Остатки и финансовые сверки | Разные планы счетов, валюта отсутствует, закрытый счёт активен |
| E06 Card | Выпущенный платёжный инструмент: card_id, account_id, agreement_id, holder_customer_id, pan_token, status, expiry | Account, Agreement, Customer | FU/RB Cards при выпуске | Карточное обслуживание и история | Статусы не сопоставлены, дубли токенов, истёкшие активные карты |
| E07 Loan | Кредитная сделка: loan_id, agreement_id, settlement_account_id, principal, currency, rate, schedule_version, status | Agreement, Account | FU/RB Loans при выдаче | Долг, график и риск | Несогласованные проценты/остатки, отсутствует график, разная просрочка |
| E08 Posting | Одна проведённая бухгалтерская запись: posting_id, ledger_transaction_id, account_id, payment_id?, dc, amount, currency, booking_date, reversal_of? | Account, Payment, Posting | FU/RB Core при проводке | Точное зерно финансовой аналитики | Повтор доставки, пропуск, несбалансированная группа проводок, смешение authorization с posting |
| E09 Payment | Поручение на движение денег: payment_id, debtor_account_id, external_creditor_ref, amount, currency, status, idempotency_key | Account, Posting | Платёжный модуль FU/RB Core; канал лишь подаёт заявку | Отличить намерение от проведённых записей и retries | Повторное исполнение, потерянный финальный статус, неверный получатель |
| E10 Product | Вид банковского предложения: product_id, code, family, name, valid_from/to, eligibility_version | Agreement, Tariff | Продуктовая команда через каталог | Единая продуктовая линейка | Одинаковые коды с разным смыслом, неверное семейство |
| E11 Tariff | Версия набора ставок/комиссий: tariff_id, product_id, version, valid_from/to, fee_rules | Product, Agreement | Продуктовый владелец, исходно Core/Cards/Loans | Сохранить договорные условия после унификации | Пересечение периодов, перенос нового тарифа на старый договор |
| E12 Branch | Место обслуживания: branch_id, bank_id, local_code, address, status, valid_from/to | Account | Банковские справочники/Core | Отчётность по сети и миграционные когорты | Коллизии кодов, переименование, закрытое отделение |
| E13 Segment | Версия классификатора: segment_id, code, definition, valid_from/to | Customer | CRM/бизнес-владелец справочника | Сравнимые клиентские витрины | Разные правила сегментации, отсутствие истории |
| E14 Case | Обращение: case_id, customer_id, agreement_id?, channel, type, status, opened_at, closed_at, restricted_text_ref | Customer, Agreement | FU/RB CRM из каналов/контактного центра | Единая история обслуживания | Дубли обращений, потеря SLA, ПДн в свободном тексте |
| E15 Consent | Доказуемое разрешение/отзыв: consent_id, customer_id, purpose, scope, legal_basis, valid_from/to, revoked_at, evidence_ref | Customer | CRM при волеизъявлении/проверке основания | Целевое использование контактов и защита | Утерян отзыв, слитые согласия разных юрлиц, неясная цель |
| E16 Document | Метаданные файла: document_id, agreement_id?, customer_id?, object_key, hash, mime_type, classification, retention_rule | Agreement, Customer | KYC/CRM/профильная система; файл в закрытом object storage | Договорные и KYC-доказательства, отдельная защита payload | Нет файла при наличии ссылки, неверный hash, лишняя копия |

E01–E16 — бизнес- и опорные сущности решения, не полный банковский бухгалтерский план. Ровно один current Segment у Customer — упрощение для выбранной отчётности, изменения хранятся исторически. Классификаторы валют, статусов, ролей и каналов ведутся как версионированные reference sets в MDM, а не как один неограниченный справочник с произвольными полями.
