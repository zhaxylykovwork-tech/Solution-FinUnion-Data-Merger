# Стратегия хранения

| Тип | Данные и роль | Выбор / отказ и ограничение |
|---|---|---|
| OLTP | Account, Posting, Payment, Agreement; карточные и кредитные сущности | Сохраняются профильные Core/Cards/Loans; ACID и бизнес-инварианты у мастера. Не переносим проводки в Hub. Новая общая OLTP СУБД всего банка не нужна для результата 3 месяцев |
| MDM Customer/Reference Hub | Customer, Identifier, Product, Tariff, Branch, Segment, нормализованные коды | PostgreSQL как физическое хранилище Hub плюс отдельные API, match/review engine и stewardship workflow. Одна БД без этих функций не объявляется готовым MDM. Vendor MDM рассматривается на discovery, если custom Hub не выдержит требования/стоимость владения |
| PostgreSQL DWH | Нормализованные staging/core, звезда проводок, дневные остатки, conformed dimensions, закрытые отчётные срезы | Отдельный кластер и ETL; простой SQL и управляемый запуск к 3 месяцам. Партиционирование по дате и read-реплики после замеров. Не обещаем неограниченное масштабирование row store |
| Lakehouse | История card events, канальные события, архивы RB, очищенная многолетняя история | Iceberg tables на закрытом S3-compatible storage; Trino для SQL, Spark batch для крупных преобразований. Ввод после MVP, когда есть подтверждённый объём/сканирование; не выполняет OLTP и не заменяет автоматически отчётный DWH |
| Object storage | Document payload, source snapshots, manifests, exports, резервные выгрузки | Hash/версия/retention в реестре; private bucket, encryption, lifecycle. Документы не копируются в каждый mart; аналитике — разрешённые метаданные |
| Графовая БД | Потенциальный граф связанности клиентов/контрагентов для расследований | **Assess**, не обязательный production-компонент. Сейчас связи выражаются SQL и согласованными edge-наборами; отдельная графовая БД оправдана только многозвенными запросами и benchmark с ИБ-ограничениями. Ошибочный match иначе загрязнит весь граф |
| Поисковый движок | Полнотекстовый поиск по обращениям | **Hold** для сырого текста и документов до доказанной необходимости. Для MVP используем индексированный/полнотекстовый поиск в CRM PostgreSQL либо штатный CRM поиск. OpenSearch может стать производной redacted-копией после проверки ACL, удаления и свежести; никогда мастер клиента |

Kafka — транспорт и ограниченный replay log, не вечный архив и не мастер. DataHub — business/technical catalog, не Iceberg transactional catalog. Airflow metadata DB содержит состояние задач, а не банковские данные. ESB остаётся для контрактов и синхронных команд; тяжёлые выгрузки не проходят через синхронный путь обслуживания клиента.

Граница выбора DWH/Lakehouse детализирована в [Task3](../Task3/dwh-lakehouse.md). До закупки проверяем стоимость хранения 12/36 месяцев, длительность full restore, время сверки и p95 выбранных BI-запросов на реалистичных данных; фактические объёмы в кейсе неизвестны.
