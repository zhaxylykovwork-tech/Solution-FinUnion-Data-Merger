# Четыре доменных data products

Продукт означает договорённость о смысле, качестве, доступе и поддержке, а не произвольный dump таблиц. Инфраструктуру даёт центральная data platform team, бизнес-владелец принимает качество и изменения. Полный Data Mesh не требуется.

| Продукт / домен BIAN | Данные / бизнес-цель | Owner / Consumers | Интерфейс и контракт | SLA, DQ и доступ |
|---|---|---|---|---|
| DP1 Customer 360 / Party Reference Data Directory | Global ID, crosswalk, verified profile, segment, product references, consent projection; общий профиль менеджера | Customer Owner / CRM, risk, BI; marketing только разрешённые purpose | Resolve API + versioned gold events + restricted SQL view; key=global_customer_id, aliases, schema_version, match_version, as_of, quality_status | Approved gold ≤5 мин при events, DWH ≤2 ч; unique current mapping, no unresolved auto-merge conflict; контакты по роли/цели, массовый crosswalk закрыт |
| DP2 Ledger Daily / Position Keeping + Current Account | Проведённые записи, daily balances, native currency turnover; единые финансы | Главный бухгалтер / Finance, регуляторный reporting, аудит | Certified DWH views и signed D+1 package; posting business key, bank/date/currency, watermark, metric_version, report_version | D+1 08:00 внутренний gate; 0 необъяснённых count/sum/balance differences; только read financial role, tokenized accounts |
| DP3 Loan Portfolio / Consumer Loan + Corporate Loan | Principal, interest, overdue, schedule version, customer/contract refs; сопоставимый кредитный портфель | Loans Owner / risk, Finance, product managers | Versioned daily SQL snapshot + manifest; loan_id+as_of, currency, definition_version просрочки | D+1; totals в Loans=портфельному срезу, обязательный schedule, связь с Core; restricted financial access, без свободных KYC-текстов |
| DP4 Product Catalogue / Product Directory | Products, tariff versions, eligibility ref, FU/RB mappings; общая линейка без изменения старых договоров | Product committee / CRM, Core, Cards, Loans, BI | Read API/reference events и справочная SQL dimension; product_code+version, valid_from/to, mapping_version | Published change ≤15 мин в reference projections, BI ≤2 ч; no overlapping tariff versions, four-eyes; публичное подмножество отдельно от внутренних условий |

Для всех: каталог DataHub содержит owner/steward, sensitivity, upstream tables/events, transform SHA, consumers и runbook. Семантическое изменение — major contract version с миграционным окном; additive nullable fields допустимы после compatibility test. Deprecated версия остаётся до подтверждения consumers. On-call платформы восстанавливает доставку, steward решает смысловой конфликт, Owner определяет пригодность. Все freshness цели требуют утверждения и измерения.

DP1 продукт не является единственным master всех данных внутри Customer 360: account/loan references остаются профилями operational masters. DP2 не получает «приблизительный» финансовый итог из telemetry. DP3 не является автоматическим решением о выдаче кредита. На dashboard видно `as_of`, approved/experimental status и known quality limitations. Это отделяет техническую доступность от бизнес-пригодности.
