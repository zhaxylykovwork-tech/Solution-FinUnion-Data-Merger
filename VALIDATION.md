# Проверки и ограничения

## Воспроизводимые проверки

`python tools/validate.py` использует только стандартную библиотеку. Проверяет 25 обязательных документов Task1–Task4, локальные ссылки, E01–E16 в четырёх матрицах, корректность XML семи Draw.io/SVG, наличие PNG и полный набор F01–F20 в детальной DFD.

Синтетические финансовые проверки используют source-scoped keys, повтор и устаревшую версию события, отдельную группу reversal, суммы по валютам и отказ сверки при удалённой проводке. Временные проверки проверяют граничную дату SCD2 [from,to), сохранение суммы с unknown dimension и отдельные версии закрытого/исправленного отчёта. Это проверка выбранных инвариантов модели, не действующий банковский pipeline.

`tools/build_diagrams.py` + `tools/erd.py` воспроизводят редактируемые Draw.io, SVG и PNG по одинаковым данным. Для PNG требуется Pillow и Arial либо DejaVu Sans. При генерации проверяются границы текста/узлов. PNG просматриваются визуально; ERD разделена на 2 листа, чтобы подписи и дополнительные связи были читаемы. Формат диаграмм соответствует допустимому Draw.io; SVG/PNG — дополнительные preview.

Проверка whitespace: `git diff --check`. Каждый Task содержит README с навигацией. Источники механизмов и версия BIAN указаны в SOURCES. Полные тексты уроков, скриншоты учебной платформы, credentials и реальные банковские/личные данные в состав сдачи не входят.

## Что не испытано

Доступа к реальным схемам/данным банка нет. Не выполнены производственная миграция, нагрузочные/DR/security tests, проверка законодательства, процессинговая сертификация или Finance sign-off. Connector choices, SLA/RPO/RTO, retention и сроки являются предложениями с gates; unknown values явно названы в README. Реальные тесты и критерии приёмки описаны в Task2–Task4 и должны предшествовать промышленному Go.

Публичность GitHub, состав PR и подтверждение сдачи требуют отдельных внешних действий. Наличие локальных файлов и успешных проверок не означает отправку в Практикум.
